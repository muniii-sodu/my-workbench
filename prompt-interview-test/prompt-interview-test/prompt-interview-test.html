VIDEO CORE

视频核心：一道实操题的"照妖镜"效应

抖音博主"可颂AI产品经理"在视频中分享了一个面试场景：面试AI产品经理候选人时，给一道实操Prompt题，就能迅速测出候选人对AI交互的真实理解水平[1]。这道题的核心不是考你Prompt写得多漂亮，而是考你是否理解AI产品交互的本质是语言和意图，而非界面布局和按钮位置。

01
实操题：设计一个"AI面试问答生成器"
看似简单，实则考察AI PM全套思维

面试官给候选人的题目是：设计一个AI面试问答生成器的Prompt。这个生成器需要根据用户输入的面试信息，自动生成高质量的面试问题和参考回答。

大部分候选人的回答停留在表面——直接写一段"你是一个面试官，请生成面试题"的Prompt就交差了。但真正优秀的候选人会做完全不同的事情。

关键区分点 优秀候选人不会急于写Prompt，而是先拆解产品核心变量——这个生成器到底需要哪些输入？输出要满足什么约束？用户在什么场景下使用？然后再设计分层Prompt策略。
02
AI产品交互的核心：语言和意图
不是界面布局，不是按钮放在哪里

视频中一个核心判断标准是：候选人对"AI产品交互核心"的理解。传统产品经理的思维惯性是画原型、排界面、定按钮位置。但AI产品的交互核心完全不同——它是语言和意图[1]。

这不是说界面不重要，而是说界面的设计逻辑变了。传统产品的界面是"功能入口"，AI产品的界面是"意图表达通道"。你设计的不是用户点哪里，而是用户怎么说、说什么、系统怎么理解。

如果你还在纠结"生成按钮放左边还是右边"，说明你还没理解AI交互。你应该纠结的是"用户该怎么描述他的需求，系统该怎么解析这个描述"。
03
产品核心变量拆解
优秀候选人的第一步不是写Prompt，而是拆变量

视频中提到，优秀候选人拿到"AI面试问答生成器"这个题目后，第一步是拆解产品核心变量[1]：

  • 面试岗位：不同岗位的面试问题完全不同，产品经理问产品Sense，工程师问技术深度
  • 问题类型：行为面试、技术面试、案例面试、压力面试，每种类型的生成逻辑不同
  • 真实性判断：生成的问题是否贴近真实面试场景？是否过于模板化？如何保证质量？
面试加分点 当你能说出"这个生成器需要至少三个输入变量——岗位、题型、难度，并且每个变量影响Prompt的不同部分"时，面试官就知道你具备AI PM的系统思维，而不是只会写一句"请帮我生成面试题"。
FRAMEWORK

五层Prompt设计框架

视频中提到，设计方案分为五层[1]。这五层构成了一个从"为什么做"到"怎么做"再到"做成什么样"的完整设计链路。每一层都对应了Prompt工程的一个关键维度，也是评估AI PM候选人思维深度的标尺。

第一层
决策设定（Decision Setting）

回答"这个AI产品为什么存在"。不是写Prompt的技术层，而是产品决策层：这个生成器的核心价值主张是什么？它解决什么用户的什么痛点？在什么场景下使用？

示例 "AI面试问答生成器的核心价值是帮助求职者在10分钟内获得针对性的面试准备材料，而非在网上漫无目的地搜索面经。目标用户是正在准备面试的求职者，使用场景是面试前1-3天的集中准备期。"
第二层
考察方向（Examination Direction）

回答"AI应该生成什么"。这一层定义AI的输出方向——不是具体内容，而是输出的考察维度。对于面试问答生成器，这意味着确定：面试官在考察什么能力？每个问题背后对应的考核点是什么？

示例 "针对产品经理岗位，考察方向包括：产品Sense（需求洞察、优先级判断）、数据分析能力（指标拆解、AB测试设计）、沟通协作能力（跨部门协作、冲突处理）、行业认知（竞品分析、趋势判断）。每个生成的问题必须标注它考察的是哪个方向。"
第三层
回答结构（Answer Structure）

回答"AI的输出应该长什么样"。这一层定义输出的格式和结构——是纯文本还是结构化JSON？包含哪些字段？参考答案以什么形式呈现？是否有追问建议？

// 结构化输出示例 { "question": "你如何判断一个需求是否应该用AI技术解决？", "type": "情景面试", "difficulty": 4, "examines": ["商业判断力", "技术选型能力"], "reference_answer": { "framework": "需求价值评估 + AI可行性判断 + 成本收益分析", "key_points": ["用户价值是否足够大", "AI是否是最优解", "模型能力边界"], "common_mistakes": "为了AI而AI，忽略传统方案的性价比" }, "follow_ups": ["如果模型准确率只有80%，你怎么设计用户体验？"] }
第四层
真实约束（Real Constraints）

回答"AI不能做什么"。这一层是防幻觉和安全边界的设计。AI面试问答生成器不能凭空编造面试题，不能生成歧视性内容，不能给出误导性答案。约束条件的设定直接反映了候选人对AI风险的认知深度[2]。

  • 事实约束：生成的面试题必须基于真实面试场景，不能编造不存在的岗位或技术
  • 伦理约束：不能生成涉及歧视、隐私侵犯、不当内容的问题
  • 质量约束：参考答案必须标注"仅供参考"，避免用户照搬
  • 范围约束：明确告知AI"如果你不确定，请说'这个问题超出我的知识范围'"[3]
第五层
用户偏好（User Preferences）

回答"如何让输出更适合这个用户"。这一层是个性化层——不同用户的面试准备需求不同，有人需要高频题刷题，有人需要深度模拟，有人需要查漏补缺。Prompt设计需要考虑如何接收和利用用户偏好信息。

示例 "如果用户标注自己是'应届生'，生成的题目偏基础概念和行为面试；如果标注'5年经验社招'，生成的题目偏架构设计和战略思维。如果用户选择'模拟面试模式'，系统以交互式问答形式运行，而非一次性输出所有题目。"
层级 核心问题 对应Prompt技术 候选人水平信号
决策设定 为什么做这个产品 System Prompt的角色定义 能讲清产品价值主张
考察方向 AI应该生成什么 任务拆解 + Few-shot示例 理解面试考核逻辑
回答结构 输出长什么样 输出格式规范 (JSON/Markdown) 具备结构化思维
真实约束 AI不能做什么 负面提示 + 安全边界 理解AI风险与幻觉
用户偏好 如何个性化 动态变量注入 + 条件分支 以用户为中心的设计思维
CANDIDATE LEVELS

候选人水平三层模型

根据视频内容和补充调研，面对同一道Prompt实操题，候选人的回答可以清晰地分为三个水平层级[1][2]。这个分层模型也是面试官心中的评分标准。

初级：表面型回答

直接写一段"你是一个面试官，请根据以下信息生成面试题"的Prompt。没有变量拆解，没有输出结构定义，没有约束条件，没有用户偏好考虑。本质上只是把需求翻译成了自然语言，没有产品思维。

中级：结构型回答

能拆解产品变量（岗位、题型、难度），定义输出格式（结构化JSON），加入基本的约束条件（不生成不当内容）。具备结构化思维，但缺少对AI交互本质的理解和个性化设计。

高级
深度型回答：五层完整设计 + 交互本质理解

高级候选人不仅完成五层设计，还能讲清楚为什么这样设计。他们能回答以下追问：

  • "为什么选择结构化JSON输出而不是自然语言？" → 因为前端需要解析渲染，JSON便于程序化处理和版本管理
  • "如果模型生成的面试题质量不稳定怎么办？" → 引入评估机制，设置质量阈值，低于阈值的自动重新生成，同时收集用户反馈做数据闭环[4]
  • "用户输入信息不完整时怎么处理？" → 设计意图澄清机制，主动追问缺失的关键变量，而非猜测后直接生成
  • "这个Prompt在什么情况下会失效？" → 当用户输入的岗位非常冷门或跨领域时，模型可能缺乏足够的训练数据，需要设计fallback策略
面试官心中的判断 当候选人能主动讨论"Prompt失效场景"和"质量评估机制"时，面试官就知道这个人不只是会写Prompt，而是真正理解AI产品的不确定性管理。
INTERACTION INSIGHT

AI交互核心：从界面到意图的范式迁移

这道面试题的深层考察点不是Prompt写法，而是候选人对AI交互范式的理解。传统产品经理的交互认知是GUI（图形界面）逻辑，AI产品经理需要升级到LUI（语言界面）甚至Intent-Centric（以意图为中心）逻辑[3]。

01
传统GUI逻辑：用户寻找功能
界面是功能入口，用户通过导航找到目标

在传统产品中，交互的核心是信息架构和导航设计。用户想听歌，要先找音乐App，再找搜索框，再打字。PM的工作是设计清晰的导航路径，让用户最快地找到功能入口。

这种思维下，PM关注的是：页面跳转逻辑、按钮摆放位置、信息层级、操作流程。界面的本质是"功能目录"。

02
AI LUI逻辑：系统理解意图
界面是意图表达通道，用户用语言描述需求

AI产品的交互核心变成了语言和意图。用户不再寻找功能入口，而是直接用自然语言描述需求。系统的工作是理解这个意图，并给出正确的响应[3]。

这种思维下，PM关注的是：用户会怎么描述需求？系统怎么解析这些描述？当描述模糊时怎么追问？当意图矛盾时怎么处理？

对话框只是AI交互的婴儿期。如果一个操作点击两次就能完成，强迫用户输入一句话就是设计的倒退[3]。
03
Intent-Centric逻辑：界面消失，意图透明
AI主动感知情境，预判用户需求，主动交付结果

交互的终局是"不交互"——最好的交互是AI已经预判了你的需求并主动交付[3]。这不是科幻，而是正在发生的趋势：

  • 生成式UI（Generative UI）：界面不再预设，而是根据AI预测的意图实时生成。聊出差行程时，界面自动弹出航班、酒店、天气对比表格
  • 主动交付（Anticipatory UX）：从"拉取"到"推送"。设定了8点会议，AI发现路况拥堵，7点就提示提前出门并启动车辆预热
  • 情境感知（Context Awareness）：在智能座舱中，你看向窗外地标并问"那是什么"，系统结合眼动追踪和高精地图直接回答
面试核心洞察 微软亚洲研究院 + 港科大提出的IAI模型指出：AI时代的交互不该只有"写prompt"，而是"prompt + 各种交互形态"的混合体。专家技能正在从"Prompt Engineering"转向"Instruction Design"[3]。
PRACTICE

Prompt工程实践要点

结合视频内容和跨源调研，以下是在AI产品设计中设计高质量Prompt的实践要点[2][5]。

设计要素 作用 实践要点 常见错误
角色设定 提升专业性和输出质量 具体到岗位+经验+风格，如"你是有10年经验的AI产品面试官" 只写"你是面试官"，过于宽泛
任务描述 明确AI要做什么 动词开头，包含输入变量和输出目标 任务描述模糊，AI不知道输出什么
约束条件 控制输出边界，防幻觉 明确"不要做什么"，设定事实边界 只写正向要求，忽略负面约束
输出格式 保证可解析和一致性 指定JSON/Markdown/表格，给出字段定义 让AI自由发挥格式，前端无法解析
示例参考 对齐输出质量标准 提供2-3个高质量输入输出样例 不给示例，导致输出风格不稳定
动态变量 实现个性化 用占位符标注可变部分，如{{岗位}}{{题型}} 把所有信息硬编码进Prompt

AI PM的Prompt工程素养

AI产品经理的Prompt能力不是"会写漂亮的提示词"，而是能系统性地设计Prompt策略：理解System Prompt和Few-shot的作用边界，知道什么时候该拆分成多步Chain-of-Thought，能判断一个效果问题是Prompt不够好还是模型能力本身不够[5]。你还要理解Temperature、Top-P这些采样参数对产品体验的影响——创意写作场景需要高随机性，而客服问答需要高度确定性。

PITFALLS

AI交互设计三条避坑指南

来自人人都是产品经理深度文章的三条实战避坑指南[3]，每一条都是面试中可以主动提及的加分点。

01
保留"逃生舱"
AI意图识别永远存在概率性错误

无论AI多么智能，其意图识别永远存在概率性的错误。界面上必须永远有一个显眼的、确定性的"手动干预"按钮，防止AI陷入逻辑闭环[3]。

在面试问答生成器的场景中：用户如果觉得AI生成的问题方向不对，必须能手动指定"我只要行为面试题"或"只要关于数据分析的题"，而非被迫接受AI的判断。

02
拒绝"黑盒式"等待
展现AI的思考过程，缓解用户焦虑

AI处理复杂任务需要时间。不要只给一个Loading转圈，要通过交互展现AI的"思考过程"——如逐步显示推理步骤[3]。

在面试问答生成器的场景中：生成过程中可以显示"正在分析岗位要求 → 正在匹配面试题库 → 正在生成参考答案 → 正在质量校验"，让用户知道系统在做什么，而非盯着空白页面等待。

03
不要为了AI而AI
知道何时该用对话框，何时该用按钮

传统的进度条、开关、单选框，在特定场景下依然比对话更高效。顶级PM的功力，在于知道何时该给用户一个对话框，何时该给用户一个简单的物理按钮[3]。

在面试问答生成器的场景中：岗位选择用下拉菜单（确定性高、选项有限），难度调节用滑块（直观、连续），只有"特殊要求"用自由文本输入。不要让用户在对话框里打字"我要产品经理岗位中等难度的行为面试题"——这比点几下按钮累多了。

INTERVIEW TEMPLATE

面试回答模板

当面试官给你一道Prompt实操题时，以下是一个结构化的回答框架，帮助你系统性地展示AI PM思维。

STEP 1 先理解题目，不急于写Prompt
话术："在写Prompt之前，我想先拆解一下这个产品的核心变量。我认为这个面试问答生成器需要至少三个输入维度——岗位类型（决定考察方向）、问题类型（决定生成逻辑）、用户背景（决定个性化程度）。请问面试官，您希望我针对哪个具体场景深入设计？"

为什么这样做：展示你不会盲目执行，而是先做产品分析。同时通过追问，把开放式题目收敛到你擅长的方向。
STEP 2 展示五层设计框架
话术："我会从五个层面设计这个Prompt——第一层决策设定，定义这个生成器的核心价值和场景；第二层考察方向，确定AI应该生成什么类型的问题；第三层回答结构，用结构化JSON定义输出格式；第四层真实约束，设定安全边界和防幻觉策略；第五层用户偏好，实现基于用户背景的个性化。"

为什么这样做：展示你具备系统性的设计思维，而非碎片化的Prompt写法。五层框架让面试官看到你的思考深度。
STEP 3 写出核心Prompt并解释设计考量
话术："这是核心Prompt的设计——角色设定为'有10年经验的AI产品面试官'，因为具体角色比泛化角色输出质量更高。任务描述使用动词开头并包含三个动态变量。约束条件明确标注'不生成涉及歧视的内容'和'如果不确定请说明'。输出格式定义为JSON，因为前端需要解析渲染。"

为什么这样做：不只是展示Prompt本身，更展示你每个设计决策背后的理由。面试官要的是判断力，不是模板。
STEP 4 主动讨论失效场景和评估机制
话术："这个Prompt在两种情况下可能失效：一是用户输入的岗位非常冷门，模型缺乏训练数据；二是用户的需求描述过于模糊。对于第一种，我会设计fallback策略，当置信度低于阈值时提示'该岗位面试题库较少，建议参考相近岗位'。对于第二种，我会引入意图澄清机制，主动追问。此外，我会设计质量评估指标——生成问题的真实性（与真实面经的相似度）、参考答案的准确性（人工抽检）、用户满意度评分（ thumbs up/down），形成数据闭环。"

为什么这样做：这是区分中级和高级候选人的关键。能主动讨论失效场景和评估机制的候选人，展示了对AI不确定性的深刻理解和产品闭环思维。
STEP 5 升维到交互本质
话术："最后我想说，这个Prompt设计的本质不只是写好一段提示词，而是理解AI产品交互的核心——语言和意图。传统产品的交互是用户找功能，AI产品的交互是系统理解意图。所以我在设计时，不只考虑Prompt本身，还考虑了用户怎么输入信息（下拉菜单+滑块+自由文本的组合而非纯对话框）、系统怎么展示思考过程、以及用户怎么干预AI的判断。这才是AI产品经理在Prompt设计中应该展现的完整思维。"

为什么这样做：把回答从"Prompt写法"升维到"AI交互认知"，展示你不只是执行者，而是具备产品哲学的思考者。
SUMMARY

总结：Prompt题考的不是Prompt，是产品思维

核心要点

  • 一道Prompt题测的不是写法，是思维：表面型回答只写Prompt，深度型回答先拆变量、定框架、设约束、讲理由
  • 五层框架是AI PM的标配：决策设定、考察方向、回答结构、真实约束、用户偏好——缺一层都不完整
  • AI交互核心是语言和意图：不是界面布局，不是按钮位置。PM的关注点从"功能入口"变成"意图表达通道"
  • 交互演化趋势不可逆：从GUI（用户找功能）→ LUI（系统理解意图）→ Intent-Centric（界面消失，主动交付）
  • 三条避坑指南是面试加分项：保留逃生舱、拒绝黑盒等待、不为AI而AI——每条都展示你对用户体验的深度思考
  • 失效场景讨论是区分关键：能主动讨论Prompt何时失效、如何评估质量、如何设计数据闭环，才是真正的高级AI PM

面试官的终极判断标准

面试官给这道题，不是为了看你Prompt写得多漂亮。他要看的是：你拿到一个AI产品需求时，第一步做什么？你是否理解AI交互的本质？你能否系统性设计而非碎片化输出？你能否预判风险并设计闭环？

一句话总结：Prompt题是AI PM的照妖镜——照出的是产品思维，不是文字功底。
